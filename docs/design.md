# 简易雷达报警系统 —— 设计方案（逐步细化中）

本文档随讨论逐步细化，自顶向下记录已确定的方案。未确定的地方标注【待定】。模块划分、信号接口和编码约定见同目录 `modules.md`。

文档分两部分：「一、状态机层次」按自顶向下拆解主流程；「二、功能模块细化」记录被状态机调用、但本身有独立时序细节的功能模块（比如测距、点阵驱动等），避免细节混进状态机流程描述里。

# 一、状态机层次

## 第一层：顶层状态机

```
OFF（SW7=0：所有显示/声音/舵机都停）
  │ SW7=1
  ▼
SELFTEST（开机自检，持续2秒）
  │ 2秒后自动进入
  ▼
STANDBY（待机，持续2秒）
  │ 2秒后自动进入
  ▼
SCANNING（扫描工作，持续运行，直到SW7=0）
```

**SW7 就是全局复位键**：内部 `rst = ~SW7`（复位高有效，沿用之前实验 `always@(posedge clk or posedge rst)` 的写法）。因此 OFF 不是状态机里的一个真实状态，而是"复位中"：

- SW7=0 时所有计时器、寄存器、状态机、扫描序列、模式选择（回到默认SCAN_STEP）全部清零，所有输出必须处于熄灭态：数码管位选全关、LED=0、点阵行列全关、蜂鸣器=0、Trig=0、舵机信号脚=低（不发PWM，舵机停止转动）、LCD不显示。
- SW7=1 时释放复位，状态机从 SELFTEST 开头开始。中途任何时刻拨回0都会回到复位态，重新拨1再从头开始。
- 自检2Hz闪烁的起始相位由复位后计数器从0开始自然确定（进入自检先亮）。
- SW7 不需要消抖：抖动只会导致系统多重启几次，稳定后即正常。
- 自检期间舵机：不发PWM（保持不动），STANDBY 时才回0°。
- 【待确认】SW7 拨到哪一侧是高电平（决定 `~SW7` 的极性），随引脚一并确认。

## 第二层：SCANNING 内部子状态

```
SCANNING
 ├─ SCAN_STEP（基本要求：0°→45°→...→180°→...→0°，离散8个停点，每点停2秒测一次距离）【开机默认进入】
 └─ SCAN_CONT（提高要求：0°↔180°连续匀速往返，边转边测，配合LCD雷达图）
```

- 两个子状态本质是同一个"通用扫描节拍"循环，只是"角度步长"和"每档节拍时长"两个参数不同，具体见第三层。
- SCAN_STEP ↔ SCAN_CONT 的切换由**某个按键**触发（具体是哪个物理按键/引脚号【待定】，暂不细化引脚）。
- 开机（进入 SCANNING 时）默认状态为 **SCAN_STEP**。

## 第三层：SCAN_STEP / SCAN_CONT 共用的"通用扫描节拍"

真正意义上的"连续"扫描在数字系统里也是离散的——本质上 SCAN_STEP 和 SCAN_CONT 是同一个循环，只是"角度步长"和"每档节拍时长"两个参数不同。两个子状态复用同一个循环结构：

```
通用扫描节拍(角度步长, 每档节拍时长):
  1. 舵机目标角度按"步长"前进一档，在 0°~180° 之间来回反弹
  2. 等待"每档节拍时长"（覆盖舵机转动到位 + 超声波测距，见下方参数推导）
  3. 节拍时长结束时已经拿到一次测距结果（每档只测一次，不重复测）——测距本身的时序细节见「二、功能模块细化 → 测距模块」
  4. 刷新 DISP7~5=当前角度、DISP3~0=距离值(或"----")
  5. 角度就近取整到 0/45/90/135/180 中最近一档 → 更新对应方向寄存器 → 刷新点阵上该方向线的颜色（按距离分级，见「二、功能模块细化 → 距离分级」）
  6. 刷新LED/蜂鸣器报警（按距离分级，同一套分级规则）
  7. 刷新LCD（把本次距离写进距离表对应的 5° 一格，屏上替换这一格的点）
```

两个子状态就是这个通用节拍套不同参数：

| 参数 | SCAN_STEP（基本要求） | SCAN_CONT（提高要求） |
|---|---|---|
| 角度步长 | 45° | 2°（推导见下） |
| 每档节拍时长 | 2秒（前500ms为舵机稳定时间，随后触发一次测距（≤约30ms），其余时间维持显示不变） | 约100ms（推导见下） |
| 单程(0→180)总时长 | 4档 × 2秒 = 8秒 | 90档 × 100ms = 9秒 |
| 一整圈(0→180→0)总时长 | 8档 × 2秒 = 16秒 | 约18秒 |

**SCAN_STEP 稳定时间 = 500ms 的依据**：SG90空载约0.1~0.12s/60°，45°一步约0.1s；最坏情况是切换模式/进入扫描时从180°回0°，约0.36s，500ms可覆盖并留有余量（舵机上装有超声波模块，有负载和惯性）。STEP模式不区分步长，统一用500ms。

**SCAN_CONT 参数推导**：这一档的时长下限由硬件能力决定，而不是随便定的。
- SG90舵机：典型转速约60°/0.1s（空载），转过2°这种小步幅所需物理时间几乎可忽略，远小于测距耗时，不是瓶颈。
- HC-SR04超声波：一次触发到出结果，最长要等Echo超时（对应4000mm量程≈23.5ms，即前面定的超时阈值），另外模块规格书建议两次触发间隔≥60ms以避免上次回波干扰。所以**一档节拍的下限实际上由测距耗时决定，约60~100ms**。
- 取角度步长2°、节拍100ms，一整圈约18秒，和STEP模式的16秒接近（视觉上接近"匀速连续转动"而不是"一格一格跳"），数值上留有微调空间（比如压到88ms节拍或2.25°步长可以更精确对齐16秒）。

# 二、功能模块细化

## 测距模块（ultrasonic）

- Trig：给一个 ≥10us 的高脉冲触发测距。
- 模块内部自动发 8 个 40kHz 脉冲并监听回波，Echo 端输出一个高电平，宽度 = 声波往返时间。
- 距离换算：`distance(mm) = echo_high_time * 340m/s / 2`。
- 有效量程 20mm~4000mm。**超出量程的判定方式**：给 Echo 等待一个超时时间（对应4000mm往返时间 ≈ 23.5ms，超时阈值取略大于此值，比如 25~30ms【待定具体取值】），超时还没等到 Echo 变化就判定为超出测量范围，对应显示"----"。

## 距离分级（distance banding）

PDF已给出明确边界，点阵配色和LED/蜂鸣报警共用同一套分级：

| 距离范围 | 点阵颜色 | LED |
|---|---|---|
| ≥800mm | 绿色 | 4个蓝色LED常亮，蜂鸣器不发声 |
| 600~800mm | 黄绿色 | 4个绿色LED，2Hz闪烁 |
| 400~600mm | 黄色 | 4个黄色LED，2Hz闪烁 |
| 200~400mm | 橙色 | 4个红色LED，2Hz闪烁 |
| <200mm | 红色 | 16个LED全部，2Hz闪烁 |
| 超出量程(≥4000mm/无回波) | 绿色 | 同≥800mm档（4个蓝色LED常亮，蜂鸣器不发声）|

蜂鸣器随距离变化"越近越急促"映射（自拟，参考倒车雷达节奏习惯）：

| 距离档位 | 蜂鸣节奏 |
|---|---|
| ≥800mm / 超出量程 | 不发声 |
| 600~800mm | 响100ms / 停900ms（约1Hz间歇） |
| 400~600mm | 响100ms / 停400ms（约2Hz间歇） |
| 200~400mm | 响100ms / 停150ms（约4Hz间歇） |
| <200mm | 持续响（不间断） |

音调固定用约2kHz方波（1MHz时钟分频产生），只变节奏不变音高。

## 点阵显示模块（matrix）

图2-1（点阵待机图案）经过精确读取像素坐标后，可以拆解为5条从同一圆心发出的角度线（行1~8从上到下，列1~8从左到右）：

```
共同圆心：(row5, col4)

90°线： (1,4) (2,4) (3,4) (4,4) (5,4)   — 正上方竖线
45°线： (5,4) (4,5) (3,6) (2,7)         — 右上对角线
135°线：(5,4) (4,3) (3,2) (2,1)         — 左上对角线
0°线：  (5,4) (5,5) (5,6) (5,7)         — 正右横线
180°线：(5,4) (5,3) (5,2) (5,1)         — 正左横线
```

待机图案（STANDBY）就是这5条线同时点亮、全部绿色。

SCANNING 状态下复用同一张像素表，数据流：

```
distance_memory（5个寄存器，对应0/45/90/135/180这5个物理方向，
                 各自保存"该方向最近一次测得的距离分级颜色"，
                 只有该方向被舵机再次扫到时才更新，其余时间保持不变）
        │
        ▼
pattern_mapper（内部：把5个方向当前颜色 映射到上面像素表 → 生成8x8位图+颜色位图）
        │
        ▼
matrix_driver（底层行扫描+列颜色输出，对应实际 row / row_color 引脚，
               可参考exp7的matrix_select/matrix_color实现思路）
```

- **5个方向寄存器的初始值 = 熄灭（不亮）**：进入 SCANNING 时、以及 SCAN_STEP↔SCAN_CONT 切换清空状态时，都复位为熄灭，某个方向被扫到并测出距离后才亮起对应颜色。PDF对"第一次扫描时点阵初始什么样"没有任何说明（只规定了STANDBY显示图2-1、以及"角度线颜色保持不变直到下次扫描更新"），此处为自拟处理。
- 圆心像素 (5,4) 是5条线的公共端点：**固定跟随"当前正在扫描的那个方向"的实时颜色**（不属于任何一个方向的持久寄存器，而是一个实时指示点）。
- 除圆心外，每条线其余的像素颜色 = 对应方向寄存器里保存的持久颜色。

## 数码管译码模块（seg_decoder）

直接复用 `exp2/seg_decoder.v` 的译码方式（`seg[6:0]`高有效、`cat[7:0]`低有效选位，BCD转七段），不重新设计。角度3位+距离4位共7位数码管按此译码，DISP7的小数点(seg[7]/PIN_51)不经过译码器，直接空出给舵机信号复用。

## LCD显示模块（提高要求：雷达图）

屏幕是 LCM12864-14（ST7565R，8080 并口，128×64），实现细节见 `modules.md` 的 `lcd_ctrl`。STEP 和 CONT 共用同一套画法：

| 阶段 | LCD内容 |
|---|---|
| OFF（SW7=0） | /RES 拉低，LCD 复位 → 显示关 |
| SELFTEST | 空白（题目的自检只要求点阵/数码管/LED；为腾资源去掉了原来的全屏闪烁） |
| STANDBY | 底边基线 + 0.2/0.4/1/2/4m 刻度（1/2/4m 旁有数字） |
| SCAN_STEP / SCAN_CONT | 显示"距离表"：37 个方向（每 5° 一格）各一段 ±2.7° 的短弧，半径 = 该方向最近一次测到的距离（≤4m；距离到半径是三段折线：0~0.4m 每级 4cm、0.4~1.2m 每级 10cm、1.2~4m 每级 40cm，近处细远处粗）；相邻同级的弧首尾相接成轮廓；扫到时替换，超量程 / 无回波时画在最外沿；切换模式时清屏 |

模型和点阵一样：每个方向保存最近一次的结果，"保持到下次扫描更新"。角度、距离的数字由数码管显示（LCD 文字行为腾资源已去掉）。
样式经过七版（见 modules.md）。

## SCAN_STEP↔SCAN_CONT 切换时机

按键消抖输出的单周期脉冲一旦出现，**立即打断**当前扫描：不等当前节拍走完，清空现有扫描状态（角度序列位置；5个方向寄存器复位为熄灭，点阵重新变暗），舵机回到0°，以新模式重新开始（角度步长/节拍时长切换为新模式对应的参数）。

## 按键消抖（复用已有模块）

SCAN_STEP↔SCAN_CONT 切换按键的消抖直接复用 `exp7/key_filter.v` 的状态机结构（IDLE/DEBOUNCE/WAIT，检测到稳定按下后输出单周期高脉冲），只需1位而不是exp7里的8位并行版本，不重新设计消抖逻辑。

## 串口数据汇报（自拟附加功能，PDF未规定）

FPGA 通过串口把扫描结果以文本形式发给电脑（或其他串口设备），只发不收。

- **链路参数**：9600bps，8数据位、无校验、1停止位（8N1）。1MHz时钟下每位104个周期，误差约0.16%；9600也是蓝牙模块HC-05/06的默认波特率，以后接蓝牙可直接复用。带宽足够：CONT模式最快每100ms一行、每行18字节（约19ms），远小于节拍。
- **格式**：ASCII文本行，任何串口助手都能直接看。
  - **测量行**（每次测距完成发一行，即STEP每2秒一行、CONT每100ms一行）：`A=045 D=0623 L=1\r\n`，共18字节，固定长度。`A`=角度(度)，`D`=距离(mm)，超量程时为 `D=----`，`L`=距离分级(0~4，含义同距离分级表：0=≥800mm或超量程，4=<200mm)。
  - ~~事件行~~（`#SELFTEST`/`#STANDBY`/`#STEP`/`#CONT`）：**不做**。资源不够（完整事件行要多约 50 LE，短码版也超 11），只发测量行。
- **复位**：SW7=0时整个模块随复位清零，TX保持空闲高电平，不发任何数据；自检、待机阶段没有测距，也不发。
- **发送忙时**：一行没发完又来了新的测量结果时，等当前行发完再发新的一行；只记最新一次，不排长队。
- **物理连接**：板上串口模块（手册第 12 节）：RX1/TX1/RX2/TX2 = 引脚 86/85/84/81，经电平转换后是 **RS232 电平的 9 针 DB9 口**（COM1 是 2 脚输出、3 脚输入，和电脑串口直连即可）。本功能用 TX1（引脚85）→ COM1。电脑端需要 DB9 串口或 **USB 转 RS232** 线（不是 3.3V USB-TTL）。板上 USB 口是 USB-Blaster，只做供电和 JTAG 下载，不提供串口（2026-10-08 查手册第 3 节确认）。
- **改用蓝牙（HC-05/06）**：逻辑不用改，数据模式下就是 9600 8N1 透明串口。题目 1 给的接法（TXD→95、RXD→94）和超声波冲突，不能用；改为杜邦线把蓝牙 **RXD 接排针上标 "85 TX1" 的那个针**（与 RS232 芯片共用同一根 CPLD 输出，3.3V 电平），VCC→3.3V、GND→GND，TXD 不接（只发不收）。手机端用"蓝牙串口"类 App（经典蓝牙 SPP，iPhone 不支持 HC-05/06），默认配对码一般是 1234。
- 除了汇报，它还是个调试工具：实现早期就能把超声波原始距离、状态等打印到电脑，比只看数码管方便。

# 模块接口设计（偏实际设计）

`design.md` 记录流程和方案；本文档把方案落到具体模块：层次、信号、编码约定。**接口在实现时可以微调，改了要回来同步本文档**。标注【待确认】的是依赖硬件信息、暂时无法定死的地方。

## 1. 设计约定

- **单一时钟域**：全部时序逻辑挂在 `clk`（PIN_18，1MHz，1个周期=1µs）上，用"使能脉冲/电平"做慢速节拍，**不生成派生时钟**（和之前实验里 `clk_4Hz` 那种写法不同；CPLD上更稳，也避免跨时钟域问题）。
- **主时钟选1MHz而不是50MHz**：exp3~exp7 已在该脚验证并沿用（`key_filter` 等复用模块的计数常数就是按1MHz算的）；之前实验的时序报告里 exp7 最高时钟仅约40.56MHz、exp6约53.41MHz，MAX II 上跑50MHz需要给组合逻辑逐个加流水线；本设计所需精度（超声波1µs=0.17mm、舵机脉宽1µs、混色子槽100µs）1MHz都够。只有LCD接口需要高速率时再考虑给LCD模块单独用50MHz（已确认 ST7565R 8080 并口，1MHz 下每字节 4µs，不需要更快的时钟）。
- **复位**：顶层 `rst = ~sw7`，高有效、异步（`always@(posedge clk or posedge rst)`），所有模块共用。复位态下所有输出必须是熄灭态（见 design.md 第一层）。
- **脉冲信号**（`xxx_pulse`/`done`/`start`/`restart`）都是**单周期高电平**；**电平信号**（`blink_2hz`）保持多个周期。
- **极性沿用之前实验**：`seg[6:0]` 高有效（1点亮）、`cat[7:0]` 低有效（0选中该位）、点阵 `row[7:0]` 低有效选行、`row_color` 列数据高有效点亮、按键按下为高电平。以上均来自exp2~exp7，实际硬件表现上板时验证。
- 语言 Verilog，顶层文件 `rtl/radar_system.v`，模块文件放在 `rtl/`，测试台 `sim/tb_xxx.v`（Quartus 工程文件留在根目录）。

## 3. 模块层次与数据流

```
radar_system
 ├─ timebase        1MHz → tick_1ms、blink_2hz
 ├─ key_debounce    btn_mode 消抖 → btn_pulse（原复用 exp7 key_filter，第7步为省资源换掉）
 ├─ sys_fsm         SELFTEST/STANDBY/SCAN 主状态机 + mode_cont 模式位
 ├─ scan_engine     通用扫描节拍：角度/舵机脉宽/触发测距的时序
 ├─ servo_pwm       20ms周期PWM
 ├─ ultrasonic      Trig/Echo时序 + 距离(BCD) + 超量程判定
 ├─ dist_band       距离(BCD) → 距离分级
 ├─ angle_bcd       角度(二进制) → BCD，仅用于显示
 ├─ result_reg      测距完成时锁存本次结果（角度、距离、分级、方向）
 ├─ dir_mem         5个方向的持久颜色寄存器
 ├─ matrix_ctrl     按阶段/方向颜色生成每行8列的颜色码（pattern_mapper）
 ├─ matrix_driver   行扫描 + 红绿PWM混色 → row / row_color
 ├─ disp_ctrl       按阶段拼出8位数码管显示内容
 ├─ seg_scan        8位数码管动态扫描 + 译码（复用exp2译码，补"-"和空白）
 ├─ alarm_ctrl      分级 → 16个LED
 ├─ buzzer_ctrl     分级 → 蜂鸣器
 └─ lcd_ctrl        LCD12864 雷达图：8080 写时序、初始化、按角度维护的距离表（37 格，每格画一段短弧）、按表重画字节
 ├─ report_ctrl     每次测距把结果拼成一行 ASCII 文本
 └─ uart_tx         9600bps 8N1 发送
```

一次测距的数据流：`scan_engine` 给出角度并发 `meas_start` → `ultrasonic` 测完发 `done` + `mm_bcd`/`oor` → `dist_band` 得分级 → `result_reg` 在 `done` 时同时锁存角度、距离、分级 → 数码管/LED/蜂鸣器按锁存值刷新，`dir_mem` 写入对应方向颜色。

## 4. 公共编码

**phase（2位，sys_fsm输出）**：`0`=SELFTEST，`1`=STANDBY，`2`=SCAN。（复位态不属于任何phase，因为整个系统在复位。）

**band（3位，距离分级）**：`0`=≥800mm或超量程，`1`=600~800，`2`=400~600，`3`=200~400，`4`=<200，`7`=尚无数据。

**color（3位，点阵颜色码）**：`0`=灭，`1`=绿，`2`=黄绿，`3`=黄，`4`=橙，`5`=红。分级到颜色：`color = band + 1`（band=0、超量程都是绿）。

**dir_idx（3位，方向）**：`0`=0°，`1`=45°，`2`=90°，`3`=135°，`4`=180°。由角度就近取整得到：角度<23→0，<68→1，<113→2，<158→3，其余→4（STEP的45°步长恰好落在5个点上，CONT取整）。

**数码管符号码（4位）**：`0~9`=数字，`A`=横线"-"（只亮g段），`F`=空白。

### timebase
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst | in | |
| tick_1ms | out | 每1000个clk一个单周期脉冲 |
| blink_2hz | out | 电平，每250ms翻转一次（周期500ms=2Hz）；复位后先为高，即"进入自检先亮" |
| blink_1hz | out | blink_2hz 每次由低变高时翻转（周期1000ms）；复位后为高。给 buzzer_ctrl 做 1000ms 节奏 |
| beat_100ms | out | 每个250ms段的前100ms为高。给 buzzer_ctrl 做"响100ms" |
| tone_2k | out | 微秒计数器第8位，约2kHz方波，给 buzzer_ctrl |

### key_debounce
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst, tick_1ms | in | |
| key | in | 按下为高 |
| pulse | out | 单周期脉冲：每 10ms 采样一次，连续两次采到按下才发，松开前只发一次（与 exp7 key_filter 行为相同） |

原先原样复用 exp7 的 `key_filter`（8 路并行 + 自带 16 位分频），只用 1 路却占 40 LE；加上 LCD 后器件放不下，换成复用 `tick_1ms` 的单路版本，8 LE。

### sys_fsm
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst, tick_1ms | in | |
| btn_pulse | in | 模式切换脉冲 |
| phase[1:0] | out | 见公共编码；SELFTEST 2s → STANDBY 2s → SCAN，之后停留在SCAN |
| mode_cont | out | 0=SCAN_STEP，1=SCAN_CONT；复位为0；每个btn_pulse翻转（仅SCAN阶段响应） |

### scan_engine（通用扫描节拍）
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst, tick_1ms | in | |
| scan_en | in | `phase==SCAN`。为0时输出回零位（pulse_us=500，angle=0） |
| mode_cont | in | 选择参数：STEP=步长45°/节拍2000ms/稳定500ms；CONT=步长2°/节拍100ms/稳定20ms |
| restart | in | 脉冲：回到0°、序列位置清零，重新开始 |
| meas_oor | in | ultrasonic 的 `oor`（上一次结果超量程），STEP 重测用 |
| pulse_us[11:0] | out | 舵机目标脉宽，500~2500µs |
| angle_deg[7:0] | out | 当前目标角度 0~180 |
| dir_idx[2:0] | out | 当前角度对应的方向（就近取整） |
| meas_start | out | 单周期脉冲：每个节拍在"稳定时间"结束时发一次 |

- 角度按步长在 0~180 间来回反弹（到端点反向），每个节拍时长到点就前进一档。
- 角度→脉宽：STEP只有5个点（500/1000/1500/2000/2500µs）；CONT每步约22.2µs，用"每步+22，余数攒够9再+1"的累加实现，避免乘除。累加值恰好等于 `floor(角度×100/9)`，端点 0°/180° 精确落在 500/2500µs（仿真已验证走满 0→180→0 后回到 500）。
- CONT稳定时间取20ms（2°转动几乎瞬时，节拍100ms内需留出测距≤约24ms+HC-SR04建议的间隔）。
- **CONT 重新开始后的第一个节拍拉长到 500ms（第480ms测距）**：按键从STEP切过来时舵机可能还在180°附近，回0°要约0.36s，只等20ms会把转动途中的读数记到0°方向。用 `first` 标志实现，STEP不受影响（本来就等500ms）。
- **STEP 超量程重测**（2026-10-22 加）：STEP 每档只测一次，"----" 要停 2 秒；第一次（500ms）若超量程，在 600ms（`ms_cnt==599`）再发一次 `meas_start`，只重测一次。隔 100ms 是因为无回波时 Echo 可能拉高约 38ms，太早再触发会被模块忽略。重测前 "----" 会闪约 100ms；重测结果照常写 result_reg/dir_mem、串口多发一行。CONT 不重测。+3 LE，全片 1262/1270。
- **`meas_start` 在节拍的第 `settle_ms` 个 tick 发出**：`ms_cnt` 从 0 开始计，所以条件是 `ms_cnt == settle_ms-1`。写成 `== settle_ms` 会晚 1ms（仿真抓到过）。
- **【资源】角度/脉宽的加减只能保留一份**。最初把"前进一档"写成 task 在 4 个分支里调用，被展开成 4 份加减法器，模块 214 LE。改成"增量算成带符号常量选择 + 单个加法器"后降到 70 LE。

### servo_pwm
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst, tick_1ms | in | |
| en | in | `phase != SELFTEST`。为0输出低，舵机不动 |
| pulse_us[11:0] | in | 高电平持续时间（在每个周期开头锁定） |
| servo | out | 20ms周期，高电平pulse_us µs |

周期数 20 个 tick_1ms（5 位计数器），周期开头把 pulse_us 装进 12 位倒计数器，非零期间输出高。
（【资源】原来是 15 位 µs 计数器 + 12 位比较器，34 LE → 28 LE。）

### ultrasonic
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst | in | |
| start | in | 触发一次测量（对应 meas_start） |
| abort | in | 中止进行中的测量，不发done（接 scan_clear） |
| echo | in | 内部两级触发器同步 |
| trig | out | start后输出约12µs高脉冲（≥10µs要求） |
| done | out | 单周期脉冲，本次测量结束（正常或超量程） |
| mm_bcd[15:0] | out | 距离，4位BCD（mm），done时有效；**直接用BCD计数，不做二进制转BCD** |
| oor | out | 超量程/无回波，done时有效 |

- 计时：Echo高电平期间每µs累加 `acc += 17`，`acc>=100` 时 `acc -= 100` 且BCD毫米计数+1，即 `mm = t_µs × 0.17`，精确、无除法。
- **超量程判定**：BCD毫米计数到达4000（对应Echo高电平约23.5ms）就直接判超量程并结束，不必等回波下降沿；另设一个"Trig后等待Echo上升沿"的超时（约10ms，参数），无回波也判超量程。这样design.md里"超时25~30ms"的待定项被取代：实际上限就是量程对应的23.5ms。
- 等的是Echo**上升沿**而不是高电平：HC-SR04无回波时Echo可能保持高38ms以上，下一次start时旧Echo还没落下，按电平判断会误测。
- 进入计数的那一拍（上升沿）就计入第1µs（`acc<=17`），计数拍数正好等于高电平宽度，结果精确等于 `floor(t×17/100)`。
- `mm_bcd` 就是计数器本身：done时有效并保持到下一次start（不另设输出寄存器）。测量中途再来的start被忽略。
- **`abort` 输入（接 `scan_clear` = restart 或 phase!=SCAN）**：中止进行中的测量、不发done。否则按键切换模式时测到一半的旧测量会在切换后才发done，把旧角度的结果写进刚清空的 result_reg/dir_mem（`tb_top.v` 抓到过）。
- 两次测量的最小间隔由 scan_engine 的节拍保证（STEP≥2s，CONT=100ms）。
- **毛刺过滤**（2026-10-22 加，板上 STEP 模式偶发假 "0"）：Echo 高电平不到 20mm（约 118µs，模块最小量程）就落下，视为干扰，回 S_WAIT 继续等真回波（10ms 超时照常计）；Echo 上升沿时清零 mm_bcd，丢掉毛刺计的数。+11 LE，全片 1259/1270。
- `tb_ultrasonic.v` 覆盖：20mm下限、各分级边界(199/200、399/400…)、999→1000进位、3999不超量程、Echo过长约23530µs判超量程、无回波10ms超时、旧Echo未落下、中途start被忽略、3µs/117µs 毛刺被丢掉后仍测出真回波、只有毛刺则照常超时。

### angle_bcd
组合逻辑：`angle_deg[7:0]`(0~180) → `bcd[11:0]`（3位BCD，百位/十位/个位）。

**不能写成 `r/10`、`r%10`**：Quartus 会各综合出一个完整除法器（54+57 LE），整个模块 131 LE。
改用 double dabble（移位加3）：百位单独判断，余下 0~99 用 7 级移位转两位 BCD，降到 18 LE。
`tb_angle_bcd.v` 穷举 0~180 全部取值验证过。

### result_reg
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst | in | |
| clear | in | `restart` 或 `phase!=SCAN`：清成"尚无数据" |
| done | in | 锁存时刻 |
| angle_bcd[11:0], mm_bcd[15:0], oor, band[2:0] | in | 来自上游 |
| dir_idx[2:0] | in | 来自 scan_engine，写 dir_mem 用 |
| r_angle_bcd[11:0], r_dist_bcd[15:0] | out | 已锁存的显示值 |
| r_valid | out | 0=尚无数据（距离显示"----"） |
| r_oor | out | 本次超量程（距离显示"----"） |
| r_band[2:0] | out | 已锁存的分级，无数据时=7 |
| r_strobe | out | 单周期脉冲：`done` 之后一个周期，表示上面的 r_* 已更新（串口汇报用它作触发） |

### matrix_ctrl（pattern_mapper）
| 信号 | 方向 | 说明 |
|---|---|---|
| phase[1:0], blink_2hz | in | |
| cur_dir[2:0] | in | scan_engine 的实时方向，用于圆心 |
| colors[14:0] | in | dir_mem 输出 |
| row_idx[2:0] | in | matrix_driver 当前扫描的行（0~7，对应图2-1的第1~8行） |
| col_on[7:0] | out | 该行哪几列点亮，bit j = 第 j 列（列0~7对应图2-1的第1~8列） |
| grp_color[8:0] | out | 三组列的颜色码：`[2:0]` 第1~3列，`[5:3]` 第4列，`[8:6]` 第5~8列 |

（【资源】原来输出每列的3位颜色码 `col_color[23:0]`，matrix_driver 再逐列查调色板，8 列各一份。
一行里只有三组颜色来源，改为"列掩码 + 三组颜色"后，driver 只查 3 次。两模块合计 136→105 LE。）

按阶段输出：
- SELFTEST：整屏黄色，`blink_2hz` 为低时全灭。
- STANDBY：图2-1的像素表，全部绿色（不闪烁）。
- SCAN：按 design.md 的像素表，每个像素取所属方向 `colors` 的颜色；圆心(5,4)取 `colors[cur_dir]`（即当前方向的颜色）。
- 像素表是固定常量（5条线共17个像素），组合逻辑实现。

### matrix_driver
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst | in | |
| col_on[7:0], grp_color[8:0] | in | 当前行的列掩码和三组颜色（见 matrix_ctrl） |
| row_idx[2:0] | out | 当前扫描行，给 matrix_ctrl |
| row[7:0] | out | 低有效行选 |
| row_color[15:0] | out | 高8位/低8位为两种颜色通道，按PWM占空混色 |

- 参考exp7：每行1ms（8行一帧=8ms，帧率125Hz）。
- **混色**：一行的 1000µs 里，前 `TH` 微秒点红、剩下的点绿。红+绿=1000µs，
  所以每个点亮的像素总点亮时间恒定，**不同颜色之间亮度一致**；红绿也永不同时点亮
  （保留exp7"红绿分时"的性质，一行电流上限和exp7一致）。
  调色板就是 5 个阈值，数字越大越偏红：

  | 颜色 | 绿 | 黄绿 | 黄 | 橙 | 红 |
  |---|---|---|---|---|---|
  | 红色时段 TH (µs) | 0 | 40 | 100 | 250 | 1000 |

  **上板实测：红 LED 比绿亮得多（约 9:1），真正的黄色在 100µs 而不是 500µs。**
  最初按"10个100µs子槽"做（分辨率 1/10），黄落在 1/10、黄绿就该在 0.5/10 —— 表示不出来，
  绿到黄之间只剩一格。所以改成直接用行内的 µs 计数器当 PWM 相位，分辨率 1/1000。
  实现上是 6 个阈值比较器 + 每组一个 6:1 选择（3 组），再按列掩码开关，比"每列各做一次比较"省资源。
- **和exp7的关键区别**：exp7 的 `matrix_color` 是 `row_color = {col,col} & {p×8,~p×8}`，
  一整屏共用一个占空比 `p`，无法让同一行的不同点显示不同颜色。本模块改成每列各自查表、
  各自判断本子槽是否点亮，才能满足"5条方向线各自一种颜色"的要求。
  保留exp7"红绿分时、不同时点亮"的性质，一行的电流上限和exp7一致。
- 复位/灭：`row=8'hFF`，`row_color=0`。

### lcd_ctrl
| 信号 | 方向 | 说明 |
|---|---|---|
| clk, rst, tick_1ms, blink_2hz | in | |
| phase[1:0], restart | in | 阶段变化、restart 时清屏、清空距离表 |
| r_strobe, r_dist_bcd, r_valid, r_oor | in | 来自 result_reg，每次测距更新距离表的一格 |
| angle_deg[7:0] | in | 二进制角度。更新在 r_strobe 后几 ms 内完成，舵机还在本档，所以不另存 |
| mode_cont, r_angle_bcd | in | 未用（原文字行） |
| lcd_d[7:0], lcd_cs_n, lcd_a0, lcd_wr_n, lcd_rd_n, lcd_rst_n | out | ST7565R 8080 并口，只写不读（rd_n 恒高） |

- **屏幕**：LCM12864-14，控制器 ST7565R，128×64，按 8 页 × 132 列寻址（后 4 列不显示），每字节是一列竖着 8 点、bit0 在上。
  初始化命令照抄课程参考程序 `LCD12864_14液晶VHDL参考文档/lcd_12864.vhd`（E2 2C 2E 2F 24 81 1C A2 C8 A0 40 B0 10 00 AF），
  `A0`+`C8` 使第 0 页在上、第 0 列在左。命令之间各等 1ms；/RES 先低 3ms 再等 6ms。
- **写时序**：每字节 4 拍（1MHz 下 4µs）：A0/数据就位+CS 低 → WR 低 → WR 高（上升沿锁存）→ CS 高。规格书要求周期 ≥240ns、WR 低 ≥140ns。
- **显示模型：按角度维护距离表，屏幕显示这张表**（用户指出"应该是在维护每个角度的距离值"）：
  - 距离表 37 格（0°,5°,…,180°）× 5 位：存「级-1」u = 0~24，31 = 无点（量程 4m = HC-SR04 全量程；画在半径 2u+1；距离 → u 为三段折线：0~400mm 每级 40mm、400~1200mm 每级 100mm、1200~4000mm 每级 400mm）。
    格数 × 位数是用户在资源内的取舍（另两种：4°×3 位、10°×6 位）；
  - 每次测距：测量角度就近落到一格（(θ+2)/5），新值替换旧值。超量程 / 无回波 → 画在最外沿（u=25，半径 51，4m 刻度之外一点）。值没变就不重画；
  - **每格画成一段短弧**（以圆心为中心 ±2.7°，比格间距的一半略宽）：相邻格距离级相同时弧首尾相接，连成物体轮廓，
    距离级不同处断开成台阶。用户要"把相近的点连起来"；真正画直线连相邻点需要读邻格、画线段、重画线段经过的所有字节，
    单独综合约 +400 LE（944 vs 545），放不下；短弧每格只画自己，不需要邻格信息；
  - 扇形圆心在底边正中 (63.5, 63)，0° 指右、180° 指左（与点阵一致）；底边基线 + 0.2/0.4/1/2/4m 刻度（3 像素高短竖线，距圆心 25/50 列）；
  - 只有 restart、阶段变化时清屏（距离表一起清空）；SW7=0 时 /RES 拉低、LCD 显示关；自检阶段 LCD 空白
    （原来用 A5/A4 全屏点亮命令跟着闪，加短弧后资源用到 1269/1270，去掉省约 10 LE）。
- **按表精确重画字节**（解决"没有显存、写一个字节会覆盖同列 8 个像素"）：要改某个字节时，从背景（基线 + 刻度）开始，
  把距离表 37 格的短弧逐个算出来，落在这个字节里的像素都 OR 进来，再一次写入。每次测距以旧弧、新弧的中心各框一个 ±4 像素的
  矩形（弧半宽 ≤2.6 像素），矩形里的字节逐个重画，约 2×18 字节 × 1.3k 时钟 ≈ 50ms（CONT 100ms 一次，来得及）。
- **画弧**：从行走得到的点 P 出发往两边各"转" 4 小步，每步 x −= y/64、y += x/64（转 1/64 弧度 ≈ 0.9°，只是移位加减），
  3 步 = 2.7°，半径只变 0.2%。坐标在折叠后的右半边算，90° 那格的弧会跨过中线，弧坐标用带符号数（4 位小数）；
  0°/180° 的弧有一半落到底边以下，裁掉。y/64 像素在 4 位小数下 = wy[12:9]（最初误取 wy[12:6]，弧宽了 8 倍，写黄金模型时发现）。
  【资源】最初画弧部分 176 LE：`ax±ex` 写在不同分支里出了两套加法器；`wleft ? 63−X : 64+X` 两个加法器；`63−Y` 一个加法器。
  改成"选基准 + 单个带进位加法器"、`64 + (X ^ {wleft})`、行号取 `~Y` 低 6 位（符号位判断是否落到底边以下）后约 100 LE。
- **距离表 = 37 级 × 4 位循环移位寄存器**：读写都在表头 tbl[0]，要访问哪一格就转到哪一格；重画时转一整圈正好依次取出每一格、
  转完回到原位。不用 37 选 1 多路选择器。找格不做除法：转表时直接判断 `(θ+2) − 表头角度 ∈ [0,4]`。
- **画法："射线行走"**：行走器用格号 k（角度 = 6k），查 sin(6k°)×128 的 16 项表得 (cos, sin)，从圆心每步 x+=cos、y+=sin，
  第 t 步就是半径 t 的像素；k>15 时用 30−k 查表、画在左半边。圆心取 63.5 使 col = {1,X} / {0,~X}、row = ~Y，无加法器。
  STEP 的 45°/90°/135° 正好落在格上（9/18/27 格）。早期 6° 一格（31 格）时 45°/135° 落在 48°/138° 上，后来用省下的资源改成 5° 一格（37 格）。
- **样式演变（每一版都按上板反馈或仿真结论改过）**：
  1. 外沿"扫描轨迹点" + 内部障碍物点 → 外沿那圈点被误认为测到了东西；
  2. 题目图 2-2 的扫描线（圆心到距离处，擦旧画新）→ 扫过之后不留痕迹；
  3. 留点 + 外环外短指针、单程结束清屏、1.2m 外环每次整圈重画 → "扫回来点就没了、三个环会飘动"；
  4. 试过"按角度更新"但没有距离表（沿射线整条擦旧点）→ 仿真里圆心附近丢一半的点；
  5. 去掉外环、虚线环只画一次、一个来回清一次屏；
  6. 去掉指针、量程 2.2m、不清屏叠加 → "越打越多，应该是在维护每个角度的距离值"；
  7. 距离表 37 格（5° 一格）、距离到级是三段折线（近处细），按表重画字节。
  8. 量程从 2.2m 改成 4m（80mm/像素，每级 2 像素 = 16cm）：3.8m 这样的距离原来被丢弃，不会显示；刻度改成 1~4m 四根。2.2m 是之前自己选的比例尺，不是题目要求；HC-SR04 本身量程就是 4m.
  9. 又改成"近处看得更细"的三段折线（线性比例下 20cm 和 60cm 只差 5 个像素，挤在圆心附近）：0~400mm 每级 40mm、400~1200mm 每级 100mm、1200~4000mm 每级 400mm；刻度改成 0.2/0.4/1/2/4m 五根。由 BCD 直接算（t=10×百位+十位，h=10×千位+百位；u=t/4、6+h、15+h/4），不做乘除，测试台按真实毫米数逐项核对，并专门测了分段边界。
  10. 无回波/超量程不再清空，画在最外沿；1/2/4m 刻度旁加数字。
- **【资源】**：第一版（CORDIC 打点 + 5×7 字模）659 LE 放不下；……；距离表版第一稿 746 LE，逐项拆掉测出 sin 表连同角度折叠约 160、
  弧形环逐点枚举约 120、距离表本身 114，压到 545；加短弧后 678 LE；之后又做了几项不改行为的压缩（清屏页/列与重画页/列共用 tpg/tcl；行走步数改倒计数；head_ang 改由 head_k×6 算出；矩形中心 pcol/prow 换成列计数 colc + 末页 pmax；sin/cos 改组合查表、去掉 wc/ws/wleft 寄存器），现 **656 LE**。
  单独综合某个模块测开销：临时工程里顶层设成该模块、`VIRTUAL_PIN ON -to *`，`quartus_map` 后看 `Total logic elements`。
- **`pmod`/函数注意**：函数体里直接引用模块信号时，`wire x = f(arg)` 只在参数变化时重算，仿真和综合不一致（上一版仿真抓到过），参数一律显式传入。
- **事件收集写在主状态机之后**：和 M_IDLE"清待办"撞在同一拍时以新事件为准，不会丢。
- 测试台 `tb_lcd.v`：ST7565 行为模型接住写操作、维护显存；测试台里另维护一份期望距离表，用与 lcd_ctrl 逐比特相同的算法
  （同一张 sin 表、同样的行走累加、同样的短弧移位）生成期望画面，**每次测距后整屏逐字节比对**（共 547 次）。场景：初始化序列、写时序、
  自检 LCD 空白、待机画面、CONT 去程（1.5m 墙 + 箱子 + 近物体）、回程箱子挪走后旧弧被擦、超量程弧消失、3.9m 画在最外沿、
  伪随机距离连扫两个来回、STEP（45°/90°/135° 落在格上）、restart 清空。

### 两套段码表不能混用

母目录里有两种七段表，各自和自己的引脚顺序配套：

| | 段码表 | `.qsf` 引脚顺序 |
|---|---|---|
| exp2 / exp3 / exp4 | 7 位，`"0"=7'b111_1110`，`seg[6]=a … seg[0]=g` | PIN_52→`seg[0]` … PIN_62→`seg[6]` |
| exp5 | 8 位标准，`"0"=8'h3F`，`seg[0]=a … seg[7]=dp` | PIN_62→`seg[0]` … PIN_51→`seg[7]` |

两者落到物理引脚上结果相同（都是 PIN_52 灭、其余亮），**但表和引脚顺序必须成对使用**，
拆开搭配显示出来就是乱码。本工程用 exp2 那一套（第 2 节引脚表即 exp2 顺序），
附带好处是 `seg` 只有 7 位、PIN_51 天然不在总线里，不用额外屏蔽小数点。

### DISP 编号方向（原【待确认】项，已由 exp5 反推确定）

exp5 的 `seg_1` 实例里 `data = {4'h2,4'h0,4'h7,4'h0,4'h5,bai,shi,ge}`，个位 `ge` 在最低 4 位、
对应 `select=0` 也就是 `com[0]`；而最左边显示的是最高 4 位。所以 **`cat[7]` = 最左边那位 = DISP7**，
与本文档 `digits[31:28]=DISP7` 的约定一致。`seg_scan` 里仍保留 `DISP_REVERSE` 开关以防板上丝印反了。

## 7. 风险与需要上板验证的点

- **逻辑单元规模**：EPM1270 只有1270个LE。全部做完占 **1267 LE（100%，余 3）**，各模块（map 阶段数）：
  `lcd_ctrl` 656、`ultrasonic` 94、`scan_engine` 82、`matrix_driver` 82、`matrix_ctrl` 71、`seg_scan` 53、
  `servo_pwm` 34、`result_reg` 33、`sys_fsm` 31、`buzzer_ctrl` 25、`dir_mem` 23、`timebase` 23、
  `angle_bcd` 21、`alarm_ctrl` 11、`disp_ctrl` 8、`key_debounce` 8、`dist_band` 5。
  为装下 LCD 做过的压缩：移除串口汇报（≈190）；key_filter 换 key_debounce（40→8）；dir_mem 去掉变量位选（46→23）；
  matrix_ctrl 按列写出两个可能的来源方向、不再"先求 owner 再七选一"（90→71）；buzzer_ctrl 的音调改用 timebase 微秒计数器第 8 位
  `tone_2k`（约 1.95kHz，半周期 256µs、回绕时一次 232µs）；ultrasonic 的 14 位计数器拆成 4 位计数 + 数 tick_1ms（超时 9~10ms）；
  seg_scan 改用 tick_1ms（实际没省：Quartus 本来就把它和 timebase 里相同的计数器合并了）；LCD 自身多轮压缩（见 lcd_ctrl 一节）。
